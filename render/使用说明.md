# 流程一 · Remotion 视频渲染服务 使用说明

这份文档面向「不熟悉 Remotion」的你，讲清楚三件事：

1. 这个渲染服务是怎么跑起来的（整体链路）
2. 你要改视频长什么样，去改哪个文件、怎么本地预览
3. 后续想把视频做精细，往哪个方向走

---

## 一、它在整个系统里的位置

流程一（全自动）在后台的完整链路是：

```
关键词
  → AI 生成 标题/描述/封面提示词（元数据 Agent）
  → Gemini 出封面图
  → AI 生成 分镜脚本 + 每段旁白文案（分镜 Agent）
  → edge-tts / ElevenLabs 把旁白文案合成语音（mp3）
  → 【Remotion 渲染服务】把封面+文字+旁白拼成竖屏成品 mp4   ← 就是这个目录
  → 打包下载
```

也就是说，前面几步都由 Python 后端（worker 容器）完成，最后「拼成视频」这一步交给这个独立的 `render` 容器。

### 为什么单独开一个容器？

Remotion 是基于 React + 无头 Chromium 的渲染引擎，运行环境是 Node.js，跟 Python 后端不是一套。所以单独做一个 Node 容器，后端通过 HTTP 调用它：

```
worker 容器  ──HTTP POST /render──▶  render 容器（Node + Chromium + Remotion）
     │                                      │
     └──────── 共享 media 数据卷 ────────────┘
        （封面、旁白 mp3、成品 mp4 都放这里互相传递）
```

关键点：`worker` 和 `render` 两个容器都挂载了同一个 `media_data` 卷到 `/app/media`。所以 worker 生成的封面/音频，render 能直接读到；render 渲染出的成品，worker 也能直接拿到。**不需要来回拷贝文件。**

## 二、目录结构

```
render/
├── Dockerfile          # 构建 Node + Chromium + 中文/emoji 字体 的镜像
├── package.json        # Node 依赖（remotion 全家桶 + express）
├── server.mjs          # HTTP 服务：收到请求就渲染，是后端调用的入口
├── remotion.config.ts  # Remotion 全局配置
├── tsconfig.json
└── src/
    ├── index.ts        # 注册入口
    ├── Root.tsx        # 声明有哪些「作品(Composition)」、画布尺寸、帧率
    └── PromoVideo.tsx  # ★★★ 视频模板本体，你要改样式主要改这里 ★★★
```

**你 90% 的时间只需要动 `src/PromoVideo.tsx` 这一个文件。**

## 三、视频数据是怎么传进模板的

后端渲染时会 POST 一段 JSON（叫 `inputProps`）给渲染服务，长这样：

```json
{
  "title": "1xBet Promo Code 2026",
  "keyword": "1xbet promo code",
  "promoCode": "NEW100",
  "coverSrc": "/app/media/content/thumbnails/xxx.jpg",
  "totalDuration": 16,
  "shots": [
    { "index": 1, "duration": 8, "scene": "画面描述", "narration": "旁白文字", "audioSrc": "/app/media/content/narration/xxx_1.mp3" },
    { "index": 2, "duration": 8, "scene": "...", "narration": "...", "audioSrc": "..." }
  ]
}
```

模板 `PromoVideo.tsx` 就是拿这些字段来画面面。**同一个模板 + 不同数据 = 批量出不同的视频**，这就是自动化批量出片的原理。

> 小细节：`coverSrc` / `audioSrc` 传进来是容器内的绝对路径（`/app/media/...`）。
> Chromium 出于安全不允许直接加载 `file://` 本地文件，所以 `server.mjs` 里会自动把这些绝对路径改写成 `http://localhost:3000/media/...` 的 HTTP 地址（渲染服务用 express 把 media 卷当静态资源托管了）。这一步已经处理好，你改模板时不用管。

## 四、我想改视频样式，怎么本地预览？（重点）

Remotion 最好用的地方是有个「所见即所得」的可视化编辑器 **Remotion Studio**，改代码它实时刷新预览，不用每次都渲染。

### 1. 装依赖（只需一次）

在你自己电脑上（不是容器里），进入 `render` 目录：

```bash
cd render
npm install
```

> Windows 上如果 `npm install` 慢，可以先换国内镜像：`npm config set registry https://registry.npmmirror.com`

### 2. 启动可视化编辑器

```bash
npm run studio
```

浏览器会自动打开 `http://localhost:3000`，左边选中 `PromoVideo`，右边就是实时预览。**你改 `PromoVideo.tsx` 保存，预览立刻变。** 这是调样式效率最高的方式。

预览用的假数据在 `PromoVideo.tsx` 里的 `defaultPromoProps`，你可以随便改成自己的测试内容。

### 3. 改样式的几个常见位置

`PromoVideo.tsx` 里已经写了中文注释，几个你最可能改的地方：

| 想改什么 | 改哪里 |
|---------|--------|
| 标题/关键词/优惠码的字号、颜色、位置 | `HeaderBlock` 组件里的 `style` |
| 文字入场动画（弹跳/淡入的快慢） | `useEntrance` 函数里的 `spring` 和 `interpolate` 参数 |
| 背景遮罩深浅 | 主组件里那层 `gradient overlay` 的 `background` |
| 每段分镜字幕的样式 | `ShotCaption` 组件 |
| 画布尺寸/帧率/时长 | `Root.tsx` 里的 `Composition`（现在是 1080×1920 竖屏、30fps）|

改完样式，**存盘即可**，不用手动编译。

### 4. 本地渲染一条看看效果（可选）

```bash
npm run render PromoVideo out.mp4
```

会用默认数据渲染出 `out.mp4`。

## 五、改完模板，怎么让线上生效？

因为渲染服务跑在 Docker 容器里，改了 `PromoVideo.tsx` 后要重建 render 镜像才生效：

```bash
docker compose build render
docker compose up -d render
```

> 这跟后端一样：改了容器里的代码，必须 rebuild 镜像。改前端 Vue 不影响它。

## 六、Remotion 官方 AI 辅助（Skills / MCP）

你提到「不会用 Remotion，需要引导」。除了看文档，Remotion 官方有几种让 AI 帮你写模板的方式：

- **官方文档**：https://www.remotion.dev/docs/ ，动画相关重点看 `spring`、`interpolate`、`Sequence` 三个概念，基本够用。
- **让 AI 帮你改模板**：你可以直接把 `PromoVideo.tsx` 贴给我，用大白话描述你想要的效果（比如「标题从左边滑进来，优惠码做一个放大高亮」），我来改代码，你在 Remotion Studio 里看效果。这是最省事的路径，不用你学 API。

建议流程：**你描述想要的效果 → 我改 `PromoVideo.tsx` → 你 `npm run studio` 看预览 → 不满意继续调 → 满意后 rebuild render 容器。**

## 七、后续精细化方向（供参考，不急）

现在是纯文字动效版（v1），够跑通链路但不够精致。后续可以往这些方向走：

1. **多套模板**：在 `Root.tsx` 里注册多个 Composition（如 `PromoVideoA`/`PromoVideoB`），创建任务时选模板。
2. **B-roll 视频素材**：分镜不只用封面当背景，可以接入短视频素材库，每段配不同画面。
3. **字幕跟读高亮**：旁白逐字/逐句高亮（karaoke 效果），需要 TTS 返回时间戳。
4. **转场动画**：段与段之间加淡入淡出、滑动等转场。
5. **背景音乐**：叠一层 BGM，用 `Audio` 组件 + 音量控制。

这些都在 `PromoVideo.tsx` 的能力范围内，等基础流程稳定后我们再逐个加。

## 八、排错速查

| 现象 | 可能原因 |
|------|---------|
| 渲染出来是黑屏 | 封面路径没传对，或 `coverSrc` 对应文件不存在 |
| 视频没声音 | 旁白 TTS 那步失败（看后台日志抽屉的「旁白配音」步骤），该段会静音 |
| 渲染很慢 | 首次请求要 bundle 打包，之后会缓存；Docker 内 Chromium 已开多进程 |
| 图片加载报 `file://` 错误 | 说明路径改写没生效，检查 `server.mjs` 的 `rewriteMediaPaths` |
| 改了模板线上没变化 | 忘了 `docker compose build render` |

查看渲染服务日志：

```bash
docker compose logs render --tail 50
```
