# 数据分析系统 — 需求文档

> 版本：v1.0
> 创建日期：2026-11-04
> 所属系统：youtube-sys
> 关联：承接「首页-总览驾驶舱」需求文档，作为整条流水线（选词→做视频→上传→刷量）的**数据反馈环节**。

---

## 一、背景与目标

现有流水线已经闭环，但缺「数据验证」这一环：视频发布/刷量后，看不到自己的视频表现，也看不到竞品是怎么做 SEO 的。

**目标**：建立一套数据分析系统，回答两个互补的问题：

1. **我的视频表现怎么样？** → 视频库数据看板（播放/点赞/评论 + 趋势）
2. **竞品是怎么做 SEO 的？** → 关键词下的竞品标题/描述/Tag 拆解

闭环逻辑：**看竞品学打法 → 用到自己视频 → 看自己数据验证效果**。

---

## 二、关键决策（已拍板）

| # | 议题 | 决策 |
|---|------|------|
| 1 | 视频库来源 | **自动关联 + 手动维护都要**（AdsPower 上传的视频自动同步 + 手动添加链接） |
| 2 | SEO 深度 | **逐条拆解 + 汇总统计都做** |
| 3 | 关键词排名追踪 | **做**（定时抓 + 趋势图） |
| 4 | 数据更新 | **定时缓存为主**，也支持**实时查询**；全局设置可配置刷新频率 |
| 5 | 板块 3（排名追踪） | **做** |

---

## 三、数据源可行性（已实测确认）

| 数据 | 来源 | 现状 |
|------|------|------|
| 视频搜索（排名） | SerpApi `search_youtube()` | ✅ 已存在（`keywords/services.py`） |
| 播放/点赞/评论/订阅/时长 | YouTube V3 `enrich_videos()` | ✅ 已存在 |
| 标题/描述/Tag | YouTube V3 `snippet` | ⚠️ V3 能拿到，但 `enrich_videos` 当前 normalize **未保留 description/tags**，开发时需扩展 |
| 我的视频链接 | `UploadTask.video_url` | ✅ 已存在（上传后回填） |
| API Key | 全局设置 `SERPAPI_API_KEY` / `YOUTUBE_API_KEY` | ✅ 已配置 |

结论：技术风险低，主要是产品形态 + 一个 `enrich_videos` 扩展点。

## 四、功能需求

### 板块 A：视频库（我的视频数据看板）

**功能**：
1. 视频列表（表格）：缩略图、标题、频道、来源（自动/手动）、播放量、点赞、评论、发布时间、数据更新时间。
2. **自动关联**：从 `UploadTask` 中所有 `video_url` 非空的记录自动同步进视频库（去重，按 `video_id` 唯一）。
3. **手动维护**：支持手动添加 YouTube 链接（解析出 video_id 后拉取数据）。
4. **单条刷新**：点某条「刷新」，实时调 V3 拉最新指标。
5. **趋势**：点某视频看播放量/点赞随时间的变化（依赖历史快照，见板块 A 的模型）。

### 板块 B：竞品 SEO 分析（重点）

**核心流程**：输入关键词 → 搜 YouTube top N → 逐条拆解 + 汇总。

**显示内容（两层）**：

1. **排名列表（top N，默认 10）**：排名、缩略图、标题、频道、订阅数、播放、点赞、评论、发布时间。

2. **SEO 逐条拆解**（点开某个视频看详情）：
   | 维度 | 拆解项 |
   |------|--------|
   | 标题 | 长度、关键词是否在开头、是否含数字、是否含 emoji、大小写风格 |
   | 描述 | 长度、首行内容（CTA/引导）、关键词密度、是否含链接、是否含时间戳 |
   | Tag | 数量、长尾/短尾分布、是否含关键词、与标题的重合度 |

3. **汇总洞察（顶部）**：top N 视频的共性规律，用规则统计产出，例如：
   - 平均标题长度 / 平均描述长度 / 平均 Tag 数
   - 「标题含关键词」的比例
   - 高频 Tag（出现次数最多的 tag）
   - 共性洞察文案（如「标题普遍 40~60 字符、关键词多放在开头、描述首行多为 CTA」）

> 第一期汇总洞察用**规则统计**产出，不调 AI（AI 建议留到后续迭代）。

### 板块 C：关键词排名追踪

**功能**：
1. 维护「追踪关键词」列表（关键词、国家/语言、top N、启用开关）。
2. **定时抓取**：按全局设置频率，对每个启用的关键词抓 top N 排名，存快照。
3. **趋势图**：选择某关键词，看其下视频的**排名随时间变化**（折线图）。
4. **手动抓取**：支持单条「立即抓一次」。

## 五、数据模型设计（新增 app：`analytics`）

### 5.1 VideoLibraryItem（视频库条目）

```

video_url       CharField
title           CharField
channel_name    CharField

upload_task     FK UploadTask, null   （自动关联来源）
flow3_run       FK Flow3Run, null     （内容生成来源，可选）
remark          CharField 备注
# —— 指标快照（最新一次抓取）——

like_count      Integer, null
comment_count   Integer, null
published_at    DateTime, null
duration        CharField（ISO8601 时长）
snapshot_at     DateTime（快照时间）

```


## 六、接口设计

| 接口 | 说明 |
|------|------|
| `GET/POST/PATCH/DELETE /api/analytics/videos/` | 视频库 CRUD（手动添加时解析 video_id 并拉数据） |
| `POST /api/analytics/videos/sync/` | 从 UploadTask 自动同步（拉所有 video_url 非空、去重） |
| `POST /api/analytics/videos/{id}/refresh/` | 单条实时刷新指标 |
| `GET /api/analytics/videos/{id}/snapshots/` | 单视频指标趋势（历史快照） |
| `POST /api/analytics/competitor/analyze/` | 传关键词 → 实时抓取 + 分析（返回完整拆解） |
| `GET /api/analytics/competitor/` + `GET /{id}/` | 历史分析记录列表 / 详情 |
| `GET/POST/PATCH/DELETE /api/analytics/rank-trackings/` | 排名追踪配置 CRUD |
| `POST /api/analytics/rank-trackings/{id}/capture/` | 手动立即抓一次 |
| `GET /api/analytics/rank-trackings/{id}/snapshots/` | 排名趋势数据 |

认证：沿用现有 JWT/Session，与其它系统一致。

## 七、数据更新策略（关键）

1. **定时缓存（默认）**：Celery beat 定时任务，按全局设置 `ANALYTICS_REFRESH_INTERVAL_MINUTES`（默认 60 分钟）执行：
   - 刷新视频库所有视频的最新指标（V3 statistics，写快照）
   - 抓取所有启用的排名追踪（写快照）
2. **实时查询（手动触发）**：竞品 SEO 分析、单条视频刷新、排名手动抓取，都是前端点按钮时直接调 API（绕过缓存、即时返回）。
3. **全局设置新增**：
   - `ANALYTICS_REFRESH_INTERVAL_MINUTES`（定时缓存频率，默认 60，可配置）

---

## 八、定时任务（Celery beat）

新增周期任务 `analytics_scheduled_refresh`（每 `ANALYTICS_REFRESH_INTERVAL_MINUTES` 分钟）：
- 刷视频库指标 + 写快照
- 抓排名追踪 + 写快照
- 无数据时直接返回（不空转）

## 十一、明确不做

- 不做播放量**历史回溯**（只从接入后开始记录快照）。
- 第一期汇总洞察用**规则统计**，不调 AI 生成 SEO 建议（AI 建议留后续迭代）。
- 不做「我的视频在某关键词下的排名」这类反向追踪（先做「关键词下 top N 排名」正向追踪）。
