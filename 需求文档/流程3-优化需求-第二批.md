# 流程3 优化需求（第二批）

> 本文档针对「内容生成系统（流程3）」的 8 项优化做可行性分析与方案设计。
> 范围仅限 `backend/flow3`、`render`、`frontend` 中流程3 相关部分，与关键词系统、流程1/2 完全隔离。
> 请评审确认后再进入编码。

## 总体评估结论

| # | 需求 | 可行性 | 复杂度 | 需迁移 | 说明 |
|---|------|--------|--------|--------|------|
| 1 | 录屏素材库支持多个 | ✅ 已基本支持 | 低 | 否 | 当前 `screen_record` 已可批量存，仅取用逻辑需调整 |
| 2 | 创建任务可选录屏素材 | ✅ | 低 | 是 | Run 加 `screen_material` 外键 |
| 3 | 失败任务「手动重试」按钮 | ✅ 幂等已内建 | 中 | 否 | 复用幂等跳过，从失败步骤继续 |
| 4 | 更新时间 → 开始/结束时间 | ✅ | 低 | 是 | Run 加 `started_at`/`finished_at` |
| 5 | 有 hook 素材则跳过 hook 文案 Agent | ✅ 已实现 | 低 | 否 | 现逻辑已如此，仅需确认并完善 |
| 6 | 批量生成视频（数量 < hook 库数量） | ✅ | 中高 | 否 | 一次创建拆成 N 个 Run |
| 7 | Agent 管理：单独运行某 Agent | ✅ | 中高 | 否 | 新增「试运行」接口，可批量产 hook 入库 |

整体可行，无阻塞性风险。涉及 2~3 个数据库迁移，均为新增字段/新增表（向后兼容，不破坏现有数据）。

## 需求 1：手机录屏素材库支持多个录屏素材

### 现状
- `Flow3Material` 的 `screen_record` 类型本就可存多条（无数量限制）。
- 问题在**取用逻辑**：`tasks.py` 目前取「最新启用的第一个」录屏（`order_by("-created_at").first()`），等于只用最新那个。
- 前端素材库录屏区是「单个上传」（`:multiple` 未开），且无多选删除。

### 方案
- 前端录屏区改为与 Hook 区一致：批量上传（`multiple`）、多选删除、列表展示。
- 取用逻辑配合需求 2 调整（指定则用指定，否则随机/取启用的）。

### 影响文件
- `frontend/src/components/Flow3System.vue`（录屏区模板 + 批量上传/多选删除函数，复用 Hook 区已有实现）
- 后端 `batch_upload` / `bulk_delete` 接口已存在，直接复用。

## 需求 2：创建任务支持选择录屏素材

### 方案
- `Flow3Run` 新增 `screen_material` 外键（可空，`SET_NULL`）。
- 创建任务时可选录屏素材（按文件名下拉，复用 Hook 素材的下拉交互）；不选则随机取一个启用的录屏。
- `tasks.py` 取录屏逻辑：`run.screen_material` 优先，否则在启用的 `screen_record` 里随机（用 `layout_seed` 做种子，便于复现）。

### 影响文件
- 后端：`models.py`（加字段）、迁移、`serializers.py`（RunCreate 加 `screen_material`）、`tasks.py`（取用逻辑）
- 前端：创建表单加「录屏素材」下拉

## 需求 3：失败任务「手动重试」按钮（从失败点继续）

### 现状
- 装配流程 `_run_assembly` **已内建幂等跳过**：每步检查产出是否已存在（narration/tts/blur_bg/tail/metadata/thumbnail/segb/segc），已完成则 `skipped`。
- 因此「从失败点继续」天然可行——只要重新触发装配，已完成的步骤会自动跳过，从失败那步继续。

### 方案
- 后端新增 `retry` action：
  - 仅允许 `failed` 状态调用。
  - 刷新 `task_token`、清空 `error_message`、状态置 `running`。
  - 若已有 `hook_video`（素材或已上传）→ 派发 `continue_flow3_run`（从 Step4~7 失败点继续）。
  - 若连 hook 都没有（极少见，卡在出 prompt 前）→ 派发 `process_flow3_run`。
- 前端：任务列表行操作列加「重试」按钮（仅 `failed` 显示）。
### 按钮位置（已确认：两个都做）
- **顶部工具栏**：新增「重试」按钮，与「新增任务」「删除」并排；作用为「批量重试选中的失败任务」（仅对选中项里 `failed` 的生效）。
- **行内操作列**：每条 `failed` 任务各自显示「重试」按钮，单条重试。
- 两种入口都调用同一 retry 接口。

### 影响文件
- 后端：`views.py`（retry action + 可选 bulk_retry）
- 前端：`Flow3System.vue`（工具栏重试 + 行内重试）

## 需求 4：更新时间 → 开始时间 / 结束时间

### 现状
- 列表展示 `updated_at`。`run_log` JSON 里有 `started_at`/`finished_at`，但未作为独立字段、未在列表展示。

### 方案
- `Flow3Run` 新增 `started_at`（首次进入 running 时写）、`finished_at`（completed/failed 时写）两个 `DateTimeField(null=True)`。
- 列表「更新时间」列替换为「开始时间 / 结束时间 / 耗时」。耗时 = finished - started，前端计算展示（如 `3分20秒`）。

### 影响文件
- 后端：`models.py`（2 字段）、迁移、`tasks.py`（写入时机）、`serializers.py`（输出字段）
- 前端：列表列调整

## 需求 5：有 hook 素材则跳过 hook 文案 Agent

### 现状
- 已实现！`process_flow3_run` 里 `_resolve_hook_material`：若指定或随机到 hook 素材，直接用其文件作 hook_video，**跳过 hook prompt 生成**，直接进 Step4~7。
- 仅当库中无可用 hook 素材时，才调用 Hook 文案 Agent 出 prompt 并等待人工上传。

### 方案
- 逻辑已满足，本需求主要是**确认 + 文案对齐**。
- 完善点：创建任务时若 hook 库有可用素材，前端明确提示「将直接使用素材，不调用 Hook 文案 Agent」。

### 影响文件
- 无后端逻辑改动（已满足）；前端提示文案微调。

## 需求 6：创建任务支持批量生成视频

### 规则（已确认）
- 批量数量 **不超过**（≤）所选 hook 分组中可用（未使用）素材数量。例：分组有 5 个可用素材 → 最多批量 5 个。
- 选择批量生成时，**不可再手动选 hook 素材**，强制随机。
- 每个视频 = 一个独立 Run，各自随机取一个「未使用」hook 素材（互不重复），用过标记「已使用」。
- 可用素材范围受需求8 的「hook 分组」约束：批量只在创建任务所选 hook 分组内取未使用素材。

### 方案
- 创建表单加「生成数量」(默认 1)。数量 > 1 即批量模式：隐藏/禁用 hook 素材下拉。
- 后端 create：
  - 校验 `count < 可用未使用 hook 素材数`（批量模式）。
  - 循环创建 `count` 个 Run（共享关键词/优惠码/时长等入参），各自不指定 hook_material（走随机）。
  - 为避免并发随机撞车：创建时就**预分配**不同的未使用素材给各 Run（而非都等执行时随机），保证不重复。
- 返回创建的 Run 列表。

### 关键设计：批量模式下的 hook 预分配
- 单个随机在并发下可能多个 Run 抢同一素材。批量模式改为：create 时一次性取 `count` 个未使用素材，逐个赋给各 Run 的 `hook_material` 并标记已使用，再分别派发。

### 影响文件
- 后端：`views.py`（create 支持 count + 预分配）、`serializers.py`（加 `count` 入参，非模型字段）
- 前端：创建表单加「生成数量」+ 批量模式下禁用 hook 下拉 + 提示规则

### 上限规则（已确认：不超过）
- 批量数量上限 = 所选 hook 分组内「未使用」素材数量（可相等）。例：5 个可用 → 最多批量 5 个。
- 前端实时显示「当前分组可用未使用 hook 素材 N 个，最多可批量 N 个」；超出则禁止提交。
- 后端 create 校验 `count <= 分组内未使用素材数`，否则报错并拒绝创建。

## 需求 7：Agent 管理 — 单独运行某个 Agent

### 目标（已确认）
- **主目的：调试提示词**。在 Agent 管理页单独运行某个 Agent，填临时输入即可立即看到该 Agent 的产出，方便反复调优提示词，无需创建完整任务跑全流程。
- **次要：产出 prompt 文本**。可多次运行 Hook 文案 Agent，批量得到多条 hook prompt 文本，导出供人工去外部引擎生成视频。
- 视频**依然由外部生成**，系统不负责产 mp4（不涉及接入文生视频 API）。

### 分析
- Agent 产出依赖上下文（keyword / promo_code / country）。单独运行需提供**临时输入**，不依赖某个 Run、不建 Run、不消耗素材。
- 各 Agent 试运行产出：
  - Hook 文案 Agent → 文生视频英文 Prompt（可运行 N 次得多条，供复制/导出）
  - 语音文案 Agent → 分段旁白（含 {promo_code} 替换预览）
  - 模糊底图 / 尾图 Agent → 英文生图 Prompt
  - 元数据 Agent → 标题/描述/封面提示词
- 产出仅用于**查看调试**，不写库、不下载视频。

### 方案
- 后端新增 Agent「试运行」接口 `POST /api/flow3-agents/<id>/run_once/`：
  - 入参：`keyword`、`promo_code`、`country`（临时上下文，不建 Run）。
  - 按该 Agent 类型调用对应生成函数，返回产出（prompt 文本 / 文案 / 生图 prompt 等）。
  - Hook Agent 支持 `repeat`（运行次数，默认 1），返回多条 prompt。
- 前端 Agent 管理页增强（UI 风格不变）：
  - 每个 Agent 卡片加「试运行」区：填临时关键词/优惠码 → 运行 → 展示产出。
  - Hook Agent 额外支持「运行 N 次」批量产 prompt，结果可复制/导出。

### 影响文件
- 后端：`views.py`（Agent run_once action）、`services.py`（复用现有生成函数）
- 前端：`Flow3System.vue`（Agent 管理区增强）

### 已确认
- 定位为**调试工具 + 产 prompt 文本**，视频仍外部生成，不接入文生视频 API。

## 需求 8：hook 素材库分组（增删改查）

### 方案
- 新增模型 `Flow3MaterialGroup`：`name`、`is_default`、`created_at`，流程3 专属。
- 系统内置「默认分组」，不可删除。
- `Flow3Material` 加 `group` 外键（可空，`SET_NULL`；空视为默认分组）。
- 上传 hook 素材时选择归属分组，不选→默认分组。
- 创建任务时**必须选择一个 hook 使用分组**：随机/批量只在该分组的未使用素材中取。

### 分组增删改查
- 列表 / 新建 / 重命名 / 删除（删除分组时，组内素材转移到默认分组，不连带删素材）。
- 接口：`/api/flow3-material-groups/`（标准 CRUD）。

### 影响文件
- 后端：`models.py`（新模型 + Material 加 group）、迁移（建表 + 字段 + 建默认分组）、`serializers.py`、`views.py`（分组 ViewSet；materials 按 group 过滤；batch_upload 接收 group）
- 前端：素材库 Hook 区加分组管理（下拉切换 + 增删改）、上传选分组；创建任务加「hook 分组」下拉（必选）

### 已确认
- 分组**仅对 hook 素材生效**（录屏/BGM 不分组）。
- 创建任务时所选 hook 分组若无可用未使用素材：**直接报错、阻止创建任务，并弹出报错原因**（如「所选分组『XXX』无可用未使用的 Hook 素材，无法创建任务」）。批量模式下同理：数量超过该分组可用数也报错阻止。

## 数据模型变更汇总

```
# 新增
class Flow3MaterialGroup(models.Model):
    name = CharField(max_length=100, unique=True)
    is_default = BooleanField(default=False)   # 默认分组不可删
    created_at = DateTimeField(auto_now_add=True)

# Flow3Material 新增
group = ForeignKey(Flow3MaterialGroup, null=True, blank=True, on_delete=SET_NULL, related_name="materials")

# Flow3Run 新增
screen_material = ForeignKey(Flow3Material, null, blank, SET_NULL, related_name="screen_used_by_runs")
hook_group      = ForeignKey(Flow3MaterialGroup, null, blank, SET_NULL)  # 批量/随机取 hook 的分组
started_at      = DateTimeField(null=True, blank=True)
finished_at     = DateTimeField(null=True, blank=True)
```

迁移计划：
1. 建 `Flow3MaterialGroup` 表 + 建「默认分组」数据 + `Flow3Material.group` 字段 + 存量 hook 归入默认分组。
2. `Flow3Run` 加 `screen_material`/`hook_group`/`started_at`/`finished_at`。

均为新增（向后兼容，不破坏现有数据）。
